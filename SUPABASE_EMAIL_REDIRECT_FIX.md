# Fix Supabase email confirmation on a phone

## Why the old flow failed

While the app runs locally, its origin is something like `http://localhost:5174`. If you register from that local app and open the confirmation email on your phone, `localhost` means the phone itself—not your computer. The phone cannot reach the development server using that URL.

## Correct production setup

1. Deploy the `citypulse` folder to Vercel using the steps in `DEPLOY_NOW.md`.
2. Copy the HTTPS URL that Vercel assigns to the project, for example `https://citypulse-example.vercel.app`. Use your actual deployment URL, not the example.
3. Vercel → Project → Settings → Environment Variables: set `VITE_SITE_URL` to that exact URL (no trailing slash) for Production. Keep the existing `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and `VITE_MAP_STYLE_URL` variables too.
4. Redeploy the site after changing environment variables.
5. Supabase Dashboard → Authentication → URL Configuration:
   - Site URL: the same exact public HTTPS URL.
   - Redirect URLs: add the exact URL and an app-route pattern like `https://your-actual-domain.vercel.app/**`.
   - Local development can keep `http://localhost:5173/**` and `http://localhost:5174/**` as separate entries.
6. Register a new test account from the deployed public site and open the confirmation email on your phone. Do not use confirmation links generated by a local `localhost` session.
7. Ensure the `supabase/migrations/20261025000004_auth_profile_provisioning.sql` migration has completed successfully. It provisions profiles even when email confirmation is enabled and signup returns no active session.

## What this project changed

- Signup calls Supabase Auth with `emailRedirectTo` set to `VITE_SITE_URL/`.
- Password reset uses `VITE_SITE_URL/reset-password`.
- If `VITE_SITE_URL` is not set, local development falls back to the current browser origin. This fallback is useful for local desktop testing, but it is not appropriate for opening a localhost email link from a separate phone.

## Security note

Only use the Supabase publishable/anon key in `VITE_SUPABASE_ANON_KEY`. Never put a `service_role` or secret key into any `VITE_*` variable.
